# Plan 05-03: Reduced-Motion Handling — GSAP Skip Logic

## Objective

When `prefers-reduced-motion: reduce` is active, GSAP must skip all tweens in addition to the CSS suppression already in `base.css`. Implement this by wrapping all GSAP animation calls in `main.js` with a `matchMedia` check — GSAP tweens run only when the user has NOT opted into reduced motion.

## Context

`base.css` (Block 6, lines 121–126) already suppresses all CSS animations and transitions via:
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

This handles the CSS side of ANIM-08. What remains is the GSAP side: without an explicit check, GSAP will still fire tweens (which override CSS and produce motion) even when the OS reduced-motion setting is on.

The cleanest approach for a static site: check `window.matchMedia('(prefers-reduced-motion: reduce)').matches` once in `main.js` and conditionally call the hero animation and `initScrollAnimations()`.

<action>
In `assets/js/main.js`, inside the `bootstrap` function, wrap the hero animation call AND the `initScrollAnimations()` call in a reduced-motion guard:

Replace:
```
gsap.from('.hero__tagline, .brand-logo, .brand-name', { ... });
initScrollAnimations();
```

With:
```
const prefersReducedMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
if (!prefersReducedMotion) {
  gsap.from('.hero__tagline, .brand-logo, .brand-name', {
    y: 30,
    opacity: 0,
    duration: 0.8,
    stagger: 0.15,
    ease: 'power2.out',
  });
  initScrollAnimations();
}
```

The `gsap.ticker.add(render)` line stays outside this guard — Three.js must keep rendering regardless of reduced motion preference (the particles are ambient, not entrance animations).

Key constraint: do NOT call `gsap.globalTimeline.timeScale(0)` — this would also freeze the Three.js render ticker.
</action>
